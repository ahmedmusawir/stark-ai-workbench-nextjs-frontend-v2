# Checkpoint export rules

Each checkpoint needing another seat returns one indexed package and Downloads copy automatically. No Director file hunt. Use Q1_attempt-001.zip / Q2_attempt-001.zip / Q4_attempt-002.zip / Q5_attempt-002.zip as appropriate; never overwrite.

Q1 includes current contract/rulings, manifest, preflight, independent draft plan, required risk/governance bodies, candidate identity/scope and proposed controls. Q2 includes approved plan/approval/Director release, actual report/matrix, candidate/environment proof, findings and relevant safe evidence/tooling. Q4 links ruled repair and new committed identity with affected/full-regression evidence. Q5 includes cleanup, final inventory/matrix, Lead dispositions and separate process measurements. Closeout includes exact Lead certificate and Architect instruction.

Every ZIP contains REVIEW_START_HERE.md and FILE_INDEX.json (path, source path, purpose, bytes, SHA256; index excludes own hash). A separate receipt records archive SHA/CRC and membership verification. Use relative traversal-free names, reject unexpected symlinks, explicit allowlists, no credentials/env/auth profiles/build outputs/private data. Selected diffs/logs are scanned before export. Design baseline may be referenced by known hash if receiver has the packet; otherwise supply the design as a separate sibling archive, not recursive nested handoffs. State completeness and any unavailable dependency clearly.

Exporting never reruns the board or manufactures a verdict. Exact next decision and owner must appear first. Include original failed attempts or accessible immutable references with hashes, never only final green summaries.
